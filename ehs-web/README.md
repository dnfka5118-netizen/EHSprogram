# EHS 통합관리 (환경안전)

점검 · 위험성평가 · 안전작업허가를 하나로 묶어 관리하는 웹 프로그램입니다.
Next.js 16 + Supabase + Vercel로 만들었고, 휴대폰에서 사용하는 것을 기본으로 설계했습니다.

## 현재 구현 범위 (1단계)

| 구분 | 상태 |
|---|---|
| 공통: 로그인, 첫 로그인 비밀번호 변경, 개인설정 | ✅ |
| 공통: 사업장, 부서(지정자/승인자), 사용자, 프로세스별 권한, 장소, 유형 | ✅ |
| 사내점검: CEO 안전점검 / 월간환경안전점검 / 공장장 안전점검 | ✅ |
| 이메일 알림 (단계별 즉시 알림 + 매일 아침 요약) | ✅ |
| 기존 엑셀 데이터 이관 스크립트 | ✅ |
| 사내점검: 유해화학물질 자체점검, 관리감독자 일일점검 | 예정 |
| 사외점검, 위험성평가, 안전작업허가서 | 예정 |

### 사내점검 처리 흐름

```
점검자      : 점검 등록 → 지적사항 등록 (장소·세부장소·유형·문제점·개선 전 사진·조치 요청 부서)
부서 지정자 : 부서 내 조치담당자 지정 (여러 명 가능, 변경 가능)
조치담당자  : 조치계획 등록 (즉시조치 / 단기대책 / 장기대책, 각각 목표일)
조치담당자  : 결과 보고
              ├ 모두 완료 → 개선 후 사진 필수 → 부서장 승인 대기
              └ 미완료   → 미완료 이유·진행현황 필수, 목표일이 지났으면 새 목표일 필수 (변경 이력 자동 기록)
부서장      : 개선 후 사진 확인 → 승인(종결) 또는 반려(사유 필수 → 조치담당자에게 되돌아감)
```

처리 권한은 화면뿐 아니라 **데이터베이스에서 강제**됩니다. `supabase/migrations/0001_init.sql`의 RPC 함수가 이를 담당합니다.

## 처음 설치하기

### 1. Supabase 프로젝트 만들기
1. https://supabase.com 에서 새 프로젝트를 만듭니다. 지역은 **Northeast Asia (Seoul)**를 권장합니다.
2. **SQL Editor**에서 아래 파일을 순서대로 붙여넣고 실행합니다.
   - `supabase/migrations/0001_init.sql` (테이블, 권한, 처리 함수, 사진 저장소)
   - `supabase/migrations/0002_seed.sql` (천안사업장 부서·장소·유형 초기값)
   - `supabase/migrations/0003_notifications.sql` (이메일 알림 대기열, 이관용 컬럼)
3. **Authentication → Sign In / Providers → Email**에서 설정합니다.
   - **Allow new users to sign up: 끄기** (계정은 관리자만 만듭니다)
   - Confirm email: 끄기
   - Minimum password length: 6 (기본값)

### 2. 환경변수 설정
`.env.example`을 복사해 `.env.local`을 만들고 값을 채웁니다. 값은 Supabase **Project Settings → API**에서 확인합니다.

```
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...      # 절대 외부 공개 금지
INITIAL_PASSWORD=000000            # 신규/초기화 비밀번호 (6자리 이상)
APP_URL=https://배포주소            # 메일 바로가기 링크
SMTP_HOST= / SMTP_PORT= / SMTP_USER= / SMTP_PASS= / MAIL_FROM=   # 메일 발송
CRON_SECRET=임의의긴문자열          # 아침 요약 메일 인증
```
자세한 예시는 `.env.example` 참고.

### 3. 첫 관리자 계정 만들기
```bash
npm install
node scripts/create-admin.mjs 본인이메일@sypchem.co.kr 홍길동
```

### 4. 실행
```bash
npm run dev      # http://localhost:3000
```

### 5. Vercel 배포
1. 이 폴더를 GitHub 저장소에 올립니다.
2. Vercel에서 **Add New → Project**로 저장소를 가져옵니다.
3. **Environment Variables**에 위 4개 값을 입력한 뒤 Deploy합니다.
4. 회사 업무용이므로 Vercel **Pro** 플랜, Supabase **Pro** 플랜 사용을 권장합니다.

## 초기 운영 순서 (관리자)
1. **환경설정 → 사용자·권한**: 사용자를 일괄 등록합니다. 엑셀에서 `이메일, 이름, 부서명, 직위`를 복사해 붙여넣으면 됩니다.
2. **환경설정 → 부서·결재자**: 부서마다 **조치담당자 지정자**와 **종결 승인자(부서장)**를 지정합니다.
3. 협력업체 계정은 **사용자 상세 → 프로세스별 권한**에서 필요한 프로세스만 `열람` 또는 `작성`으로 엽니다.
4. **환경설정 → 사업장**에서 울산사업장을 추가하고, 부서와 장소를 등록합니다.

## 이메일 알림

| 시점 | 받는 사람 |
|---|---|
| 지적사항 등록 | 조치 요청 부서의 지정자·부서장 (미지정 시 관리자) |
| 조치담당자 지정/변경 | 새로 지정된 담당자 |
| 완료 보고 | 부서장 (미지정 시 관리자) |
| 반려 | 조치담당자 |
| 종결 | 조치담당자, 등록자 |
| 지시사항 등록 | 조치담당자, 부서장 |
| 매일 08:00 요약 | 기한 초과·3일 이내 목표일(담당자), 하루 넘은 지정 대기(지정자), 승인 대기(부서장) |

- 알림은 DB 대기열(notifications)에 먼저 기록되고, 처리 직후와 매일 아침에 발송됩니다. 실패 시 최대 5회 재시도하고, 3일이 지나면 만료됩니다.
- 발송 상태와 테스트 메일은 **환경설정 → 메일 발송**에서 확인합니다.
- 아침 요약은 `vercel.json` 의 Cron으로 실행됩니다 (Vercel 환경변수에 `CRON_SECRET` 필요).

## 기존 엑셀 데이터 이관

```bash
# 1) 미리보기 : 엑셀 옆에 "이관_미리보기_*.csv" 생성 (DB 변경 없음)
node scripts/import-legacy.mjs "../1. 2026_CEO 안전점검.xlsx" --admin 관리자이메일

# 2) 사용자 일괄 등록 후 다시 미리보기 → 담당자 매칭 확인

# 3) 실제 반영
node scripts/import-legacy.mjs "../1. 2026_CEO 안전점검.xlsx" --admin 관리자이메일 --apply
```
- 월간/공장장 점검 파일은 `--module insp_monthly` / `--module insp_plant` 를 붙입니다.
- 같은 파일을 다시 실행해도 이미 이관된 행(NO 기준)은 건너뜁니다.
- 미종결 건의 담당자가 사용자와 맞지 않으면 중단됩니다. `--allow-unmatched` 를 붙이면 해당 건은 "담당자 지정 대기"로 들어갑니다.
- 이관 중에는 알림 메일이 발송되지 않습니다.

## 개발 참고
- `npm run test:db`: Supabase 없이 PGlite로 DB 처리 흐름을 테스트합니다 (권한, 단계 전환, 목표일 이력, RLS).
- 사진은 업로드 전에 브라우저에서 긴 변 1600px, JPEG로 압축합니다 (`src/lib/image.ts`).
- 월별 보고서 엑셀(사진 포함)은 Vercel 응답 크기 제한을 피하려고 브라우저에서 생성합니다.
